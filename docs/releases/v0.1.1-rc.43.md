# Proxy Pilot v0.1.1-rc.43

Windows x64 本地验证版，在 `v0.1.1-rc.42` 的基础上，修复 **Windows 登录自启计划任务在迁移 `data/` 目录、从旧版（如 `XrayPilot-*`）升级或手动删除计划任务后保存设置误报 `STARTUP_CONFLICT: Login task ownership/action changed; external task preserved` 的问题**，并补充冲突诊断日志与显式接管解除入口。**本版尚未发布到 GitHub Release**。

## 本次变化

- **修复缺失计划任务时误报 `STARTUP_CONFLICT` 死锁（`windows-integration/src/startup.rs`）**：
  - `StartupController::save` 此前只要检测到实际计划任务（`None`）与 `runtime/startup-owner.json`（`Some(...)`）不一致便一律报 `STARTUP_CONFLICT`，导致用户拷贝 `data/` 到新目录、升级自 `XrayPilot-*` 或手动删掉旧计划任务后无法修改任何设置（包括取消开机自启）。
  - 修正为仅在计划任务实际存在（`task_before.is_some()`）且与所有权记录不一致时才触发 `STARTUP_CONFLICT` 保护外部任务；当任务不存在时允许正常保存设置并自动同步更新 `runtime/startup-owner.json`。
- **增强 `startup.ps1` 规范化与 `STARTUP_CONFLICT` 诊断/恢复能力**：
  - 优化 `startup.ps1` `Normalize` 中 `Principal.UserId` 与触发器 `UserId` 的 SID 归一化逻辑，避免多余账户对象构造及用户名/SID 形式差异导致误判。
  - 新增 `StartupController::conflict_summary()`，在 `SaveSettings` 与启动恢复遇到 `STARTUP_CONFLICT` 时将任务名、存在性、所有者描述匹配及禁用状态写入 `logs/supervisor.log`。
  - 新增 `Command::ResolveStartupConflict`（GUI 错误卡/恢复横幅中的「重新接管自启计划任务…」弹窗与 `proxyctl resolve-startup-conflict`），可在存在外部修改或禁用任务时显式由当前实例按已保存设置重建/清理计划任务并解除阻塞。
  - 新增 `windows-integration`、`proxy-supervisor` 与 `proxy-manager-app` 回归测试，覆盖缺任务旧记录容错、冲突日志摘要、冲突接管恢复与 GUI 弹窗派发。
