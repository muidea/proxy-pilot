# Proxy Pilot v0.1.1-rc.42

Windows x64 本地验证版，在 `v0.1.1-rc.41` 的基础上，修复 **Windows 下 `PacServer` 接受连接继承非阻塞模式导致 `ROLLBACK_FAILED: PAC_SERVICE_UNAVAILABLE; PAC_SERVICE_UNAVAILABLE` 的问题**。**本版尚未发布到 GitHub Release**。

## 本次变化

- **修复 Windows 本地 PAC HTTP 服务 `WouldBlock` 断连缺陷（`pac_server.rs`）**：
  - `PacServer::start` 对 `TcpListener` 设置非阻塞轮询时，Windows（Winsock2）`accept()` 返回的 `TcpStream` 会继承非阻塞模式，导致工作线程 `serve()` 在请求尚未到达或回写大体积 GeoSite PAC 脚本时触发 `WSAEWOULDBLOCK` 并静默关闭连接，进而使 `apply()` 与回滚 `compensate()` 中的 `probe()` 均报 `PAC_SERVICE_UNAVAILABLE`（`ROLLBACK_FAILED`）。
  - 在 `listener.accept()` 获取连接后立即显式调用 `stream.set_nonblocking(false)`，将连接错误信息记入 `logs/supervisor.log`，统一将 `probe()` 中的读/写 I/O 错误映射为 `PAC_SERVICE_UNAVAILABLE`，并在 `ensure_pac_server` 中通过 `PacServer::is_alive()` 过滤已退出的旧监听线程。
  - 新增 `pac_server::tests::delayed_client_request_and_large_pac_body_succeed` 单元测试，覆盖延迟请求发送与 >300 KiB PAC 响应体场景；升级后完全退出旧版后台并重启，即可由 `Supervisor::recover()` 自动结算此前残留的未完成事务并解除锁定。
